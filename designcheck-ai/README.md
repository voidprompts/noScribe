# DesignCheck AI

Instant brand & accessibility design audits for startup founders. Paste a
website URL or drop a screenshot and get a scored report with prioritized,
actionable fixes.

**Stack:** Next.js (App Router) · TypeScript · Tailwind CSS v4 · Vercel-ready

## Deploy to Vercel (2 minutes)

### Option A — Vercel CLI
```bash
cd designcheck-ai
npm i -g vercel
vercel          # first deploy (preview)
vercel --prod   # production deploy
```

### Option B — Git integration (recommended)
1. Push this repo to GitHub.
2. Go to [vercel.com/new](https://vercel.com/new), import the repo.
3. Set **Root Directory** to `designcheck-ai`.
4. Framework preset: **Next.js** (auto-detected). Click **Deploy**.

### After deploying
1. In Vercel → Project → **Settings → Environment Variables**, add:
   `NEXT_PUBLIC_SITE_URL = https://your-domain.com` (your real domain or the
   `*.vercel.app` URL). Redeploy. This drives canonical URLs, sitemap, robots,
   and Open Graph tags.
2. Add a custom domain in **Settings → Domains** for best SEO.
3. Submit `https://your-domain.com/sitemap.xml` to
   [Google Search Console](https://search.google.com/search-console) and
   [Bing Webmaster Tools](https://www.bing.com/webmasters) so the site gets
   indexed worldwide fast.

## SEO features built in

- Per-page `<title>`/meta descriptions with keyword-rich copy
- Open Graph + Twitter Card tags with a custom 1200×630 `og-image.png`
- JSON-LD structured data: `SoftwareApplication` (with offers + ratings),
  `Organization`, `WebSite`, and `FAQPage` (eligible for FAQ rich results)

- Canonical URLs via `NEXT_PUBLIC_SITE_URL`
- Server-rendered landing page (crawlable content: features, how-it-works,
  testimonials, FAQ)
- Security headers via `vercel.json`

## Payments — real integrations included

The payment API routes are **fully implemented** for three providers using
their REST APIs (no SDK dependencies):

| Method | Provider | Env vars | Flow |
|---|---|---|---|
| 💳 Card | Stripe Checkout | `STRIPE_SECRET_KEY` | Hosted checkout session → verified via session status |
| 🅿️ PayPal | PayPal Orders v2 | `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_ENV` | Order created → buyer approves → captured server-side |
| 📱 GCash | PayMongo Sources | `PAYMONGO_SECRET_KEY` | GCash source → buyer approves in app → payment created server-side |

**How it activates:** the checkout calls `POST /api/checkout`. If the matching
provider key is set (in Vercel env vars), the customer is redirected to the
real hosted payment page; after paying they land on `/checkout/success`, which
calls `POST /api/checkout/verify` to confirm/capture the payment server-side
before upgrading the plan. If no key is set, checkout gracefully falls back to
**demo mode** (clearly labeled, no money moves).

### Go-live checklist
1. Copy `.env.example` values into Vercel → Settings → Environment Variables.
2. Start with test keys (`sk_test_...`, PayPal sandbox) and do a test purchase.
3. Swap to live keys, set `PAYPAL_ENV=live`, redeploy.
4. (Recommended) Add provider webhooks later for extra reliability on flaky
   redirects — the verify route already handles refresh/duplicate captures.

Code: `src/app/api/checkout/route.ts` and
`src/app/api/checkout/verify/route.ts`.

## Architecture notes

- Audit results come from a deterministic simulated engine
  (`src/lib/auditEngine.ts`) — same URL, same report. Swap `runAudit()` for a
  real analysis API (screenshot capture + vision model + axe-core) when ready.
- Reports and the active plan persist in `localStorage`
  (`src/lib/storage.ts`); no backend or database required.
